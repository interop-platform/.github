# Support

## Questions, Bugs, and Requests

Each interop-platform repository tracks its own issues. Open an issue in the repository the request concerns:

| Concern | Tracker |
|---|---|
| The Conductor workflow engine fork | [`interop-platform/conductor`](https://github.com/interop-platform/conductor/issues/new/choose) |
| The AtlasMap data mapping fork | [`interop-platform/atlasmap`](https://github.com/interop-platform/atlasmap/issues/new/choose) |
| The Syndesis integration platform fork | [`interop-platform/syndesis`](https://github.com/interop-platform/syndesis/issues/new/choose) |

These repositories are public: anyone can read their issues. GitHub Discussions are not enabled. A problem that
also exists upstream belongs in the upstream project's tracker as well. The upstream Syndesis project is archived,
so a Syndesis issue is fixed here or not at all.

- **Bugs** — use the *Bug report* form.
- **New capabilities or improvements** — use the *Feature request* form.
- **A missing test or proof of behavior that already exists** — use the *Test request* form.
- **Questions and troubleshooting** — use the closest form and add the `question` label.

A fork whose issues are disabled, or that has its own issue forms, does not show these forms; use what that
repository offers. Search existing issues first. When a request spans repositories, open one issue in each and link
them in full form (`interop-platform/atlasmap#42`).

## Repository-Specific Help

Each repository's `README.md` and `CLAUDE.md` describe how to build, run, and test it.

## Security

Never report a vulnerability in an issue, discussion, or pull request. Follow the private process in
[`SECURITY.md`](SECURITY.md).
